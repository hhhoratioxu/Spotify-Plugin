# iPhone 开播断线与补词修复

Version Date 为 `2026-11-20 22:05:15`（UTC+8）。用户反馈上一版 Dev 在 iPhone 仍会断开 Loon VPN，且补词未成功。修复以已发布 Dev 为基线。

## 手机响应处理

- 批量曲目元数据、启动配置和播放器状态只有在响应声明大小不超过 32,000 字节、格式可处理且未压缩时才等待完整正文。缺少长度或超过上限时，直接交给 Spotify。手机也保留 Spotify 在播放器状态请求上的原有缓存和压缩协商。
- 单曲元数据、歌词卡片和原生歌词允许最多 64,000 字节，有独立的实际字节检查。单曲请求仍支持未声明长度的 HTTP/2 响应。Loon 可能已为这类响应缓冲正文，脚本中的检查约束后续解析和分配。
- 单曲 JSON 进入同一曲目与完整元数据核对。身份匹配且明确缺词时，可补上歌词入口并缓存曲目、艺人和可用 ISRC。受限、身份不符或格式异常的响应沿用原文。
- 手机歌词 404 在响应头阶段处理。备用来源匹配成功才提交同步歌词，可随后翻译。找不到可靠来源时继续交付 Spotify 原响应。手机设置及原有串行网络预算保留。桌面仍按每首曲目分配查询名额。

## 验证

本地的完整导入文件回放使用实际 Loon 规则和运行脚本。日文自写夹具覆盖单曲 JSON、ISRC 署名匹配、同一录音歌词、逐行时间和中文翻译。另测不匹配、授权状态、异常数据、官方原词及 Mac 大于手机正文上限的译文。六项旧 Mac 测试的存储和并发期望已对齐上一版 Dev 的每曲目查询行为。当前核心兼容运行将当前缓存版本与 ISRC 期望写入临时测试副本，历史原件照常独立验证。[离线验证报告](../evidence/independence.json)

同一组 20 份自写启动响应中，等待完整正文的脚本从 20 次减为 9 次，选中正文合计从 1,394,354 字节降到 72,970 字节。使用 macOS JavaScriptCore 重放每个选中场景，分别保留 1、4、8 个环境直到该波结束。完整峰值、条件和哈希见 [启动回放报告](../evidence/ios-startup-memory.json)。

可在 Mac 上用上一个经过核验的 Dev 工作区重跑。

```sh
node tools/ios-startup-memory.mjs /path/to/previous-dev
```

整个 iPhone Loon VPN 扩展峰值须严格低于 40,000,000 字节。本轮没有可用的 iPhone。桌面测量范围为合成脚本进程，手机的原生 HTTP 和 VPN 缓冲、其他插件、连续播放与真实显示仍需实机验证。
