# 内存反馈与候选修补（2026-11-15）

用户在更新订阅后反馈仍会爆内存，随后确认是 iPhone 上的 Loon VPN 在“打开软件、播放音乐”时就断开，并非需要多次切歌才触发。具体手机型号/版本、Loon 错误文本及退出报告尚未取得，不能把合成压力测试判定为这次故障的已确认根因，也不能认定手机已经低于 50 MB。

本地候选分支为 `codex/spotify-memory-admission`。没有推送、创建 Release、更新已安装插件或修改 Loon/VPN。原发布工作区保留 `8cc285bd6e38a7a9e4bf2e7e38a8431cfbb4ba06`，运行对象为已发布的 `6b7bf71c62d412ad7f814e0721bd8a1dcafa96c0`。候选运行快照 `5bff1aa3e318172205c68892d7a84588031100b6` 仅存在本地，未公开；本分支生成的固定地址在上传该快照前不能用于在线安装。用户继续使用的 main 订阅没有被本次候选替换。

## 已确认的多余分配

此前的网络准入发生在正文解码和翻译准备之后。当前已有网络工作时，冷缓存的竞争回应仍会创建缓存视图、解析 JSON/Protobuf、建立词句和翻译集合，再因网络忙碌放弃查询。这些工作不会取得译文，却会增加重叠执行时的内存与 CPU 开销。

候选在读取歌词正文前检查同一个已有网络租约。没有可用缓存的竞争回应直接保留原 HTTP 状态、正文和官方译文，并使用 `no-store` 防止临时空结果被复用；不启动轮询或新网络请求。不同曲目的竞争沿用原租约退休机制，旧的 HTTP 回调必须真正结束后才能释放其资源。

完整/部分整曲译文、旧版逐行译文及同一歌曲的有效补词缓存仍可使用。原 `cache-only` 模式和来源关闭语义保留。原始大小、TTL、设置、匹配、时间戳、六个歌词来源及“中文保留、其他语言翻译”策略未删减。

手机原生包还在完整核心初始化之前执行一个小型同步检查，复用共享源码里的参数、缓存键和租约判断；忙碌的冷请求可以不建立完整核心。该检查在核心压缩后再包装，避免压缩器把核心声明移到准入之前。没有动态加载 JavaScript、`eval`、额外请求、后台任务或新的宿主 API。

## 针对“开始播放就断”的启动筛选

原核心明确透传 metadata/4、extended-metadata、bootstrap、user-customization-service/customize 和 v1/customize 的 JSON 回应，但原 Loon 手机入口仍会为这些回应选择 `requires_body=true` 的 Entry 脚本。新增过滤只使这些已证实不处理的 JSON 不再命中手机 Body Script；不把其他客户端的参数移植到 Loon，也不缩减来源或翻译。

Scroll、context-resolve、connect-state 的已支持 JSON、所有原先支持的二进制路线及真实 color-lyrics 回应继续命中；Content-Type 缺失时保留原路线。7 项配置回归覆盖不同 spclient 域名、大小写/参数/`+json` MIME、二进制、缺失类型及原状态/大小限制；另用 5 项核心测试确认被跳过的 JSON 原本就不改正文、状态或头部。

这些是合成规则与核心测试，实际启动流量的编码和频率尚未捕获。能确认减少了匹配这些条件时的无用脚本执行，不能认定已证实用户断线原因或真实节省了多少 MB。

这是共享持久存储上的协作控制，没有原子 CAS；它不能阻止宿主创建 VM，也不能限制宿主在调用脚本前缓冲的完整正文。因此不能据此保证整个 iOS 扩展低于 50,000,000 字节。

## 自动验证

新增 45 项准入/已知 JSON 透传回归，包括冷缓存竞争零正文读取、JSON/Protobuf 原响应保留、完整与部分缓存、旧逐行缓存、转义键、缓存过期、租约过期、读缓存时旧租约恰好结束、来源关闭，以及同曲/切歌的真实异步回调结算和重试。另有上述 7 项启动配置回归，共 52 项新增检查。Loon、Surge、Egern、Quantumult X、Shadowrocket 与 Mac 包使用模拟宿主验证，不能称为设备验收。

完整独立验证通过：在 Proxy 之外、无 Git 数据库的临时目录重新安装锁定依赖后构建，678 项 Node、18 项 Python、1011 项当前核心兼容、2248 项原始基线与 72 项内存测试桥均通过。原先因用户翻译政策精确替换的 8 项断言范围不扩大，125 个历史文件和 191 个来源对象保持原字节。见 [independence.json](../evidence/independence.json) 与 [本轮汇总](../evidence/memory-repair-summary.json)。这仍不代替原生设备验收。

## 两种桌面压力模型

测量使用自己的 macOS JavaScriptCore 进程、自写歌词、共享原生字符串存储及延迟合成回调。覆盖 Loon/Surge、standard/compact、1/4/8/16 个执行环境，包括填满缓存的冷翻译/补词、600 行英语、日英混合、中英片段以及大入口 JSON。16 是压力输入，不能解释为 Loon 公布的并发上限。

每种模型每个版本各 96 个新进程、696 次调用；读取内核整个进程生命周期的峰值，不减去启动开销，也不强制 GC。报告同时保留 footprint 与 resident，单位为字节。

| 模型 | 作用与限制 |
| --- | --- |
| 保留已完成环境直到整波结束 | 保守考察回收延迟，包含已 `$done` 的环境；不能冒充 Loon 的实际回收调度 |
| `$done` 返回后立即释放已完成环境 | 考察及时释放时的开销；只释放测量器持有的 JSC 对象，不强制 GC，不代表手机的实际释放时机 |

结果保留在以下原始报告；保守模型的候选峰值仍超 50 MB，不能挑选另一模型中的低值宣称解决。

| 模型 | 发布版 footprint / resident | 候选 footprint / resident |
| --- | ---: | ---: |
| 保守保留，所有场景最大值 | 59.62 / 78.66 MB | 50.46 / 62.62 MB |
| 及时释放，所有场景最大值 | 13.66 / 19.23 MB | 13.11 / 19.04 MB |

本表为十进制 MB；数据来自运行脚本测量，不包含新配置筛选所避免的宿主执行，因此没有给它虚构节省数值。

- [已发布版，保守保留](../evidence/memory-pressure-published.json)
- [候选版，保守保留](../evidence/memory-pressure-candidate.json)
- [已发布版，及时释放](../evidence/memory-pressure-published-immediate.json)
- [候选版，及时释放](../evidence/memory-pressure-candidate-immediate.json)

复现候选测量：

```sh
node tools/build.mjs
node tools/memory-pressure.mjs --runtime=candidate
node tools/memory-pressure.mjs --runtime=candidate --release-completed
```

与单独保留的发布版检出目录比较时，明确传入该目录：

```sh
node tools/memory-pressure.mjs --runtime=published --published-root=/absolute/path/to/published-checkout
node tools/memory-pressure.mjs --runtime=published --published-root=/absolute/path/to/published-checkout --release-completed
```

工具先核对发布版的 18 个固定资源哈希，拒绝把当前候选当作发布基线。所有执行环境依然只有一个等待网络的所有者；没有把并发改成串行调用来隐藏压力。

## 手机目标仍未通过

这次 Mac USB 检查没有发现 iPhone，设备工具只有 Command Line Tools，未操作 iPhone 镜像。没有读取手机的 jetsam、Loon 错误或整个 VPN 扩展峰值。用户已确认触发时机与断开对象，仍需候选版手机测试以及错误行、设备/版本来确认原因和峰值。

两种桌面模型均不含原生 HTTP/TLS 缓冲、其他插件、真实 Spotify 客户端及 iOS 扩展开销。即使桌面某种模型低于参考线，也不能证明手机低于 50 MB。候选修补只是减少了已确认的多余工作，具体手机失败原因和实机通过结论保持未确认。

本次没有播放音乐、改变系统音量、操作客户端界面、开启监听服务或访问账户凭据；没有修改父 Proxy、WeatherKit、MapKit。
